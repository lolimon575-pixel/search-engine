# NOVA Search

Экспериментальный поисковик с технической проверкой сайтов и отдельным слоем подтверждения официальности.

## Локальный запуск
```
python -m venv .venv
pip install -r requirements.txt
cd backend
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть: http://127.0.0.1:8000/

## Render
Build: `pip install -r requirements.txt`
Start: `cd backend && uvicorn app.main:app --host 0.0.0.0 --port $PORT`
Health: `/health`

NOVA сообщает результаты технических проверок и уровень подтверждения официальности на момент проверки. Это не гарантия безопасности, законности или добросовестности сайта.

## Направление развития

NOVA развивается как слой доверенного поиска: реестр официальных организаций, проверка источников и собственный индекс знаний поверх обычного веб-поиска.

Текущий MVP использует DuckDuckGo HTML и небольшой реестр официальных доменов.

## Управление профилем и безопасность

При создании подтверждения API возвращает два независимых значения:

- `token` — публичный код для файла `/.well-known/nova-verification.txt`.
- `owner_token` — приватный ключ. Его нельзя размещать на домене, публиковать или передавать в URL.

`POST /api/ownership/verify` требует оба значения. Для Checkout и Billing Portal
поле `ownership_token` содержит только приватный `owner_token`. В базе хранятся
SHA-256 хеши обоих значений. Ключ управления действует только после успешной
проверки домена и до истечения 24 часов с создания запроса. Интерфейс хранит его
в `sessionStorage`, отдельно от публичного кода.

При запуске добавляется nullable-колонка `ownership_claims.owner_token_hash`.
Существующие записи и статус домена сохраняются, но старый публичный код больше
не даёт доступ к биллингу. Для управления требуется новое подтверждение.
Изменение backend и frontend нужно выпускать вместе; откат на прежний backend
вернёт небезопасный доступ по публичному коду.
